## What to observe and why it matters

**Why an unbounded queue kills p99.** Little's law says the queue length equals arrival rate times wait time ([Little's law](/phase/1/latency-throughput#little-s-law)). Once arrivals exceed service rate, the queue grows without limit, and every request waits behind all the ones before it. On a CPU replica that serves about 4 streams with each answer taking 10 s, the service rate is 0.4 requests/s. At 0.6 requests/s, the queue grows by 0.2 per second: after 5 minutes, 60 waiting requests and a 150 s wait. Every request is now late, including the ones that would have been fine. Users time out and retry, which adds load. Throughput stays flat while latency goes to infinity.

**A bounded queue keeps the latency of admitted work.** With the default `MAX_QUEUE=8`, at most 8 requests wait, and none longer than `MAX_QUEUE_WAIT_MS`. The rest get `503` and `retry-after` in a millisecond ([load shedding](/phase/4/bulkheads-load-shedding#admission-control)). Run the flood command in the verify list: the 200s have about the same TTFT as at low load, and the 503s are instant. That is the goal: fail fast and cheap, not slow and expensive.

**Predicted wait, not queue length.** The gateway keeps an EWMA of request duration and refuses a request whose predicted wait (queue position divided by slots, times the EWMA) is already past its deadline, taken from the `x-request-timeout-ms` header. A request that will miss its deadline should not take a slot ([timeouts](/phase/4/timeouts-retries)).

**Admission is per replica.** The semaphore size equals llama.cpp's `--parallel`. Sending more than that just makes the server queue internally, where the gateway cannot see it or shed it ([admission at scale](/phase/6/llm-serving-at-scale#admission-control-priority-tiers-and-tenant-isolation)).

## How this changes at real scale

Assumptions: a GPU replica holds TPOT 30 ms up to batch 64; average output 400 tokens; average prompt 1,000 tokens prefilled at 10,000 tokens/s.

```
time per request  = prefill 0.1 s + 400 x 0.03 s  = about 12.1 s
service rate      = 64 / 12.1                      = about 5.3 requests/s per replica
queue for 2 s TTFT budget: wait = queue / 5.3  ->  queue at most about 10
```

Real engines admit by **KV memory**, not request count: vLLM admits a sequence only if free KV blocks can hold it, and preempts (evicts and later recomputes) when memory runs out. The gateway still sheds before that point, per tier, because preemption wastes the prefill already done.
